# Сборка под Linux (в разработке)

Этот документ описывает экспериментальную Linux-сборку движка `A5` (Silent Storm Reconstruction). Статус и обоснование решений — см. [`linux-port.md`](linux-port.md). Windows/MSVC-сборка (см. корневой `README.md`) не затрагивается: `CMakeLists.txt` ветвится по платформе (`if(WIN32)`/`if(UNIX)`), поведение под Windows не меняется.

## Статус (обновлено 2026-09-20, игра запускается и играбельна)

Ветка `linux-port` (от `develop`). **Движок собирается целиком и играется**: retail-установка 1.2, главное меню, выбор персонажа, первая миссия кампании — рендер через dxvk-native (D3D9 → Vulkan), игровая логика, ввод и UI работают. Проверено на GCC 16 / RTX 4060 / X11.

| Подсистема | Статус на Linux |
|---|---|
| `Misc`, `FileIO`, `Image` | **Работают** |
| `MiscDll`, `Script`, `DBFormat`, `ADOImport` | **Работают** |
| `Main` / `Game` (рендер) | **Работают** — dxvk-native, `S2_LINUX_FULL_ENGINE=ON` |
| Ввод | **Работает** — полная SDL2-реализация (`InputSDL2.cpp`): все 155 контролов ретейла, `cfg/input.cfg` биндится идентично |
| Окно/точка входа | **Работают** — `Game/WinFrameSDL2.cpp` + `Game/MainLinux.cpp` |
| БД (`ADOImport`) | Работает (`BasicDBLinux.cpp`) — только чтение готового `game.db`, COM/ADO-часть недоступна (см. [linux-port.md](linux-port.md#разбор-этапа-бд-adoimport)) |
| Головы персонажей | **Базовая геометрия** из `FaceGenHead.gdp` (`third_party/lifestudio/src/lsgdp.cpp`). Без морфинга и мимики — см. «Известные ограничения» |
| Звук (`FModSound`) | **Заглушка (no-op)**, `FMSoundStub.cpp` — тишина |
| Видео (`Bink`) | **Заглушка (no-op)**, `GBinkPlayerStub.cpp` — заставки не играются |

## Сборка и запуск

### Зависимости

- **CMake ≥ 3.21**, **GCC или Clang** (проверено на GCC 16)
- **SDL2** (`sdl2` в Manjaro/Arch, `libsdl2-dev` в Debian/Ubuntu)
- **Vulkan loader** (`vulkan-icd-loader`) + рабочий драйвер
- **meson + ninja** — для сборки dxvk-native

```
sudo pacman -S cmake gcc sdl2 vulkan-icd-loader meson ninja
```

### dxvk-native

Не вендорится (большой, живёт своим циклом релизов). Собирается отдельно:

```
git clone --depth 1 --recurse-submodules https://github.com/doitsujin/dxvk.git
cd dxvk
meson setup build-native --buildtype release -Dnative_sdl2=enabled -Dnative_sdl3=disabled \
      -Denable_dxgi=false -Denable_d3d8=false -Denable_d3d10=false -Denable_d3d11=false
ninja -C build-native
```

Vulkan-заголовки dxvk везёт в сабмодуле, отдельно ставить не нужно.

### Сборка движка

Без рендера (библиотеки, быстрая проверка компиляции — 13 целей):
```
cmake -S . -B build-linux -DCMAKE_BUILD_TYPE=Debug
cmake --build build-linux -j$(nproc)
```

С рендером (полный `Game`):
```
cmake -S . -B build-probe -DCMAKE_BUILD_TYPE=Debug \
      -DS2_LINUX_FULL_ENGINE=ON -DDXVK_NATIVE_DIR=/path/to/dxvk
cmake --build build-probe -j$(nproc)
```

`DXVK_NATIVE_DIR` — дерево исходников dxvk, собранное как выше; `DXVK_NATIVE_BUILD` по умолчанию `<src>/build-native`.

### Запуск

```
cd /path/to/Silent Storm            # каталог retail-установки
DXVK_WSI_DRIVER=SDL2 /path/to/build-probe/Game
```

Два обязательных условия:

- **Запускать из каталога игры** — движок ищет `game.db`, `res/`, `cfg/` относительно текущего каталога.
- **`DXVK_WSI_DRIVER=SDL2`** — на Linux у dxvk-native нет WSI по умолчанию, без этой переменной он бросает исключение до создания устройства (падение выглядит как `terminate()`, а не как ошибка).

Игра стартует в полноэкранном режиме. Полезное: `DXVK_HUD=fps`, `DXVK_LOG_LEVEL=none`.

## Ассеты

В репозитории нет игровых файлов. Нужна retail/Steam-установка игры: `game.db`, каталоги `res/` и `cfg/`.

## Что было исправлено по дороге

### Win32-шим (`Misc/PlatformCompat.h` / `.cpp`)

Единая точка для недостающих Win32-символов вместо россыпи `#ifdef` по движку: типы и MSVC-ключевые слова, таймеры, критические секции, потоки, события, `dlopen`-бэкенд для `LoadLibrary`, charset-конверсия через `iconv` (`CP_ACP` = CP1251, как в retail с русской локалью), файловый I/O, `_findfirst`/`_findnext`, буфер обмена и состояние клавиатуры (через хуки, которые ставит windowing-слой — `Misc` не зависит от SDL2), геометрия окна, `ResolvePath`.

**`ResolvePath`** — пути в игровых данных записаны по-виндовому (`.\cfg\intro.seq`, `Res\FaceGenHead.gdp`): бэкслеши переводятся в слеши, затем при промахе каждый компонент ищется регистронезависимо.

### Устранённые MSVC-измы

Все правки приняты и MSVC — поведение Windows-сборки не менялось:

- **Анонимные union/struct с нетривиальными членами** (`Geom.h`, `aiPosition.h`) — именованные поля + аксессоры.
- **Forward-declared enum без базового типа** — 101 объявление и 47 определений как `enum E... : int`; размер сериализуемых полей сохранён.
- **Двухфазный поиск имён** — `typename` на зависимых итераторах, `this->` на членах зависимой базы (десятки мест по `Main`).
- **`name##::`** в макросах регистрации — склейка идентификатора с `::` невалидна.
- **Явные специализации внутри класса**, `template<> static` на namespace-scope.
- **Глобальная `random`** конфликтует с POSIX `random(3)` — на не-Windows переименована в `s2_random`.
- **Регистр и разделители в `#include`** — приведены к реальным именам на диске.
- **Мёртвый код** `MinMaxTiles<>` (`DataMap.cpp`) — обращался к несуществующим полям, MSVC не проверял неинстанцированные шаблоны.

### Дефекты 64-бита (LP64)

Код был точен на 32-битной Windows и незаметно неверен с 64-битными указателями. Все под `#if`, Windows-путь сохранён дословно:

- **`CBufferedStream::LoadBufferForced`** — `nBufferStart - nPos` считалось в беззнаковой 32-битной арифметике; на Win32 указатель заворачивался и попадал куда надо, на LP64 уезжал на 4 ГБ, и `DirectRead`↔`Read` съедали стек.
- **`DataChunkString`** — UTF-16 читался через `wchar_t*` (2 байта на Windows, 4 на Linux): выпадал каждый второй символ, `"Courier"` → `"Cuir\1\24D"`. Из-за этого не находился ни один шрифт.
- **`SParticle`** — накладывался на образ файла, но на диске 34 байта против 54 в памяти; массив шёл с неверным шагом. Теперь файл разбирается по своей раскладке.
- **`LONG`/`ULONG`** — были `long` (64 бита на LP64) вместо 32-битных: портили заголовки BMP, которые пишутся на диск как есть.
- **`_findfirst`** — handle клался в `int` и обрезался (`iSaveManager.cpp`, 4 места).

### Инлайн-ассемблер

Четыре блока 32-битного MMX (`GCombiner` — скиннинг, `GfxBuffers` — расширение индексов, `2DSceneSW` — альфа-композитинг, `SWTexture` — билинейное масштабирование) переписаны на переносимый C. Это не реконструкция по догадкам: автор рядом с каждым блоком оставил закомментированный скалярный эталон под `ASSERT`, сверявшим результаты. Весь ассемблер сохранён за `#if defined( _WIN32 )`.

### Оконный слой

- **Восстановление режима экрана при выходе** — Windows возвращает его сама, X11 нет. Навешено на штатный выход, `atexit` и обработчики сигналов (`SIGINT`/`TERM`/`SEGV`/…); `SIGKILL` перехватить нельзя.
- **Захват мыши** (`SDL_SetRelativeMouseMode`) — движок рисует свой курсор, интегрируя дельты с собственным ускорением, поэтому системный указатель нужно прятать. Переустанавливается каждый кадр в `PumpMessages`: dxvk меняет режим через свой WSI мимо наших хуков и сбрасывает захват.

## Известные ограничения

- **Звук отсутствует** — `FMSoundStub.cpp` — no-op. План замены на OpenAL Soft: см. [linux-port.md](linux-port.md#разбор-этапа-звук-fmodsound).
- **Видео не играется** — `GBinkPlayerStub.cpp` — no-op, заставки пропускаются.
- **Лица не морфятся.** Головы рендерятся базовой нейтральной геометрией из `FaceGenHead.gdp`, одинаковой у всех: нет морфа по расе/полу/возрасту и нет мимики. Эти данные лежат в `.mld`-блобах внутри `Heads.res` — упакованный формат (43 именованных канала, плоского массива координат внутри нет), для которого нужен реверс `LifeStudioHeadAPI.dll`. `FaceGenHead.gdp` при этом оказался обычным OLE2 Compound File, и его `.msh` читается тривиально — см. `third_party/lifestudio/src/lsgdp.cpp`.
- **Персонажи без записи `CHead`** рендерятся без скина головы (видны только волосы/очки) — это штатное поведение ретейла, а не дефект порта: `CreateLSHead` строит скин только при наличии аниматора.
- **Инструменты содержимого** (`DataImport`, `ShaderCompiler`, `PkgBuilder`, `FontGen`, `TexConv`, `TexMipStrip`, `LSConverter`) на Linux не собираются — для запуска готового контента не нужны.
- **`SIGKILL`** оставляет разрешение экрана изменённым: `xrandr --output <OUT> --mode <WxH>`.
