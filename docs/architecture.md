# Архитектурная карта — Silent Storm Reconstruction

**Суть проекта:** реконструкция исходного кода игры Silent Storm 2003 г. (Nival) до behaviour-equivalent состояния v1.2, на основе анализа `.pdb` v1.1 и декомпиляции v1.2. Движок называется `A5` (см. `project(A5 ...)` в CMake). Сборка — Win32/x86, MSVC, CMake 3.21+.

## Ключевые модули

| Модуль | Назначение |
|---|---|
| **Misc** | Фундамент: геометрия (`Geom.h`), таймеры, RNG, строки, базовая событийная система, кастомный STL-конфиг — от него зависит почти всё. |
| **FileIO** | Работа с файлами: чанковый формат сохранений (`BasicChunk1`), упаковка ресурсов (`FilesPackage`), потоки, компрессия (`Cruncher`). |
| **MiscDll** | Логирование (`LogStream`) и консольные команды (`Commands`), общие для DLL-модулей. |
| **Image** | Загрузка/конвертация текстур: BMP/PNG/TGA/MMP (проприетарный формат), поверх zlib/libpng/libsquish (DXT-сжатие). |
| **ADOImport** | Обёртка над ADO для доступа к базе данных игры (`BasicDB`). |
| **FModSound** | Звуковой движок поверх FMOD (интерфейс через сгенерированный stub-import lib, реальная `fmod.dll` не нужна для сборки). |
| **Input** | Ввод через DirectInput8, система биндов клавиш/действий. |
| **Script** | Встроенный интерпретатор — судя по файлам (`lapi`, `lcode`, `ldo`, `lvm`, `lparser`…) это форк **Lua**, интегрированный как `Script.cpp`. |
| **DBFormat** | Табличные игровые данные, читаемые через ADOImport: ИИ, RPG-параметры, перки, сценарии, камеры, физика и т.д. (48 файлов `DataXXX.cpp`). |
| **Main** | Ядро движка и вся игровая логика (самый большой модуль, 711 файлов), включает подсистемы (см. ниже). |
| **Game** | Точка входа: `Main.cpp` (WinMain), `WinFrame` (окно приложения), линкуется с `Main` через `WHOLE_ARCHIVE` (т.к. классы самрегистрируются через глобальные конструкторы — линкер иначе их выбросит). |

### Подсистемы внутри Main (по префиксам файлов)

| Префикс | Подсистема |
|---|---|
| `ai*` | ИИ юнитов: путь, тактика, реакции, укрытия, видимость, командование (~70 файлов). |
| `G*`, `Gfx*` | Графика/рендер: сцена, материалы, шейдеры, частицы, ландшафт, скелетная анимация, тени, lightmaps. |
| `RPG*`, `rpg*` | RPG-система: инвентарь, крит.попадания, дипломатия, торговля, медали, юниты-наёмники. |
| `w*` (world) | Игровой мир/сущности: юниты, оружие, взрывы, декали, здания, состояния юнитов, тайм-based команды. |
| `i*` | Игровые UI-экраны (меню, инвентарь, карта, диалоги, перки, кредиты…). |
| `sc*`, `script*` | Скриптовые обвязки/сценарии поверх модуля Script. |
| `UI*` | Общий UI-фреймворк (окна, контролы, UIML-разметка). |

## Инструменты (отдельные консольные/GUI-приложения, тоже строятся)

| Инструмент | Назначение |
|---|---|
| **DataImport** | Импорт данных в БД (`DBFormat`). |
| **PkgBuilder** | Сборка `.pkg`-архивов ресурсов. |
| **FontGen** | Генерация шрифтов из растров. |
| **TexConv** | Конвертация текстур в MMP. |
| **TexMipStrip** | Обрезка мип-уровней текстур. |
| **ShaderCompiler** | Компиляция шейдеров (требует легаси D3DX9 из DirectX SDK June 2010; опционален — пропускается, если SDK не найден). |
| **LSConverter** | Конвертация ассетов LifeStudio (анимация персонажей). |

## Не собираемые, но сохранённые модули

- **MapEdit** (360 файлов) — редактор карт, требует проприетарные SDK Stingray/LifeMode.
- **Scintilla** — сторонний компонент редактирования текста, нужен только MapEdit.
- **OpenDynamix** (36 файлов) — обёртка над ODE (физика), нужна только MapEdit.

Их списки исходников сохранены в `sources.cmake`, но `CMakeLists.txt` их не подключает.

## third_party (генерируемые interop-заглушки)

- **zlib** (shared), **libpng** (static), **libsquish** (static) — собираются из исходников.
- **fmod**, **bink** — проприетарные DLL не включены; вместо них на этапе сборки генерируется stub-DLL с теми же экспортируемыми именами (`__stdcall`-декорации), только чтобы получить корректный `.lib` для линковки; реальные `fmod.dll`/`binkw32.dll` берутся из папки с игрой в рантайме.
- **lifestudio** — экспортирует C++ mangled-имена, импорт-либы генерируются напрямую через `lib /def`.

## Примечательные архитектурные решения в сборке

- Модули собираются как **статические библиотеки** (не DLL, несмотря на историческое имя `MiscDll`/`ADOIMPORT_EXPORTS` — это наследие оригинальной DLL-структуры, ныне всё линкуется статически в один `Game.exe`).
- `Main` подключается к `Game` через `WHOLE_ARCHIVE`, потому что движок использует паттерн саморегистрации классов через побочные эффекты глобальных конструкторов (`BASIC_REGISTER_CLASS`/`REGISTER_SAVELOAD_CLASS`) — обычная линковка отбросила бы неиспользуемые объектные файлы.
- Каждый модуль — это `StdAfx.h`-based PCH-юнит (классический MSVC precompiled header подход).
